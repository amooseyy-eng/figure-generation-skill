# 论文科研图、流程图与技术路线图

处理用户提供的论文及附件。先提取并标注可追溯的数据与研究流程，再整理技术路线和选图清单供用户确认；随后生成图片，组装最终论文和两份 PPT。以 DOCX 为主要输入；PDF 可以读取和标注，但扫描件可能需要 OCR，从 PDF 重建可编辑 Word 的排版也可能不完整。开始前按输入格式查看 [运行环境](references/environment.md)。

## 调用方式

用户可直接使用 `$paper-figure-data`，或发送：“请使用 paper-figure-data 技能处理附件论文，先阅读技能目录中的 SKILL.md 并按流程执行。论文：<文件路径>；其他附件：<文件路径或无>。”技能被调用后，先读取本文件及所需参考资料，再开始处理；不要要求用户先手动打开或复制 SKILL.md 内容。若用户已经明确给出论文和附件路径，直接开始，不重复询问。

## 文件位置

论文项目目录是用户指定的输出位置；若用户未指定，使用输入论文所在目录。不要把项目目录与安装本 skill 的文件夹混为一处，也不要在 skill 安装目录创建运行产物。原始论文和附件不移动、不改写；确需复制供处理时，放入项目目录第一层的“原始输入”。本次运行的中间产物按类别直接放在项目目录第一层的“提取数据”“输出论文”“过程文件”“图片”“临时文件”等文件夹中；最终版论文也直接放在项目目录第一层。开始处理前一次性创建下方列出的通用目录骨架；收到用户确认的选择清单后，再一次性批量创建本次入选图对应的项目目录，之后生成过程中不逐项临时建目录。只创建本流程列出的目录；完成交付时删除没有产出文件的空目录，避免遗留空目录和重复结构。

- 原始输入/：确需复制处理的原论文及附件，保留原文件名；不复制时不创建此目录
- 提取数据/：黄色标注数据段落.md、蓝色标注流程段落.md、附件数据摘录.md、技术路线图依据文段.md、提取数值.csv、科研图选择清单.csv、流程图选择清单.csv、技术路线图候选大纲.md、技术路线图选择清单.csv
- 项目目录根目录/：论文名_最终版.docx（插入已选的全部图片，最终交付的首选论文文件）
- 输出论文/：论文名_标黄版.docx（同时含黄、蓝标注）；如用户还要求最终版备份，可额外保存最终版副本
- 过程文件/：图像顺序与文件索引.csv；每张图的代码、输入数据和生成说明
- 过程文件/科研数据图/N01_FIG001/：plot.py、data.csv、生成说明.md（每张科研图一个文件夹）
- 过程文件/流程图/N02_FLOW001/：flowchart.mmd、生成说明.md（每张流程图一个文件夹）
- 过程文件/技术路线图/N03_ROUTE001/：route.svg、生成说明.md（每张技术路线图一个文件夹）
- 过程文件/组装脚本/：生成最终论文或 PPT 时实际使用的脚本（如有）
- 图片/：论文名_科研数据图.pptx、论文名_流程图.pptx
- 图片/科研数据图/：逐张科研图的 PNG/SVG
- 图片/流程图/：逐张流程图的 PNG/SVG
- 图片/技术路线图/：逐张技术路线图的 SVG/PNG
- 临时文件/：本次运行的日志、OCR/转换缓存和其他中间文件

除最终版论文外，本流程的中间文件和成品按上方目录结构放在项目目录第一层，不写进 skill 安装目录。若原文是 PDF，标注版和最终版可以按实际能力输出为 PDF，文件扩展名随格式调整；不要把 PDF 转换结果称为保留原排版的 DOCX。再次运行时不覆盖旧成果；使用新的文件名后缀，并同步更新代码中的输出路径、生成说明和图像索引。最终回复给出实际文件路径，并明确指出根目录下的最终论文。

## 1. 提取并标注原文

开始处理前，先确定项目目录，然后用一次目录初始化操作在项目目录第一层建立“提取数据”“输出论文”“过程文件/科研数据图”“过程文件/流程图”“过程文件/技术路线图”“过程文件/组装脚本”“图片/科研数据图”“图片/流程图”“图片/技术路线图”和“临时文件”。仅当确需复制用户输入时，才一并创建“原始输入”。在用户确认选择清单后，按清单中的全部入选项批量建立对应的 `过程文件/类别/N序号_候选ID` 子目录；不为未选项目建目录。每个阶段开始前，先批量建立该阶段新增的全部路径；绘图、渲染和组装阶段直接写入，不逐项临时建目录。完成核对后移除没有文件的空目录。

先检查论文正文、表格、图注和附录。论文提到补充表、原始数据，或正文数值不足以支持一张有意义的图时，按论文上下文读取用户提供的相关附件（如 DOCX、PDF、XLSX、CSV）；核对变量、组别、单位和研究对象一致后，才能将附件数据列为科研图候选。未提供或无法读取的附件记录名称与影响，不臆测数据。为每条数值记录变量、数值、单位、组别/时间点、样本量或误差类型、来源文件与具体位置及原文证据。区分正文报告、附件报告、计算结果和图中估读；图中估读仅在用户要求且可以可靠读取时进行。冲突或无法辨认的数据单独列出。

只把有明确比较、趋势、组成或变量关系，且数值足以支持图型的数据列为科研图候选。在论文标注副本中，将论文里的候选数据及必要的变量名、组别和单位标黄。若数值只在附件中，存入单独的附件数据摘录文件并标明附件位置，不能把附件数值当作论文正文已标黄。把足以独立提炼为流程图的样本流转、实验步骤、数据处理或判断分支文段标蓝；只有背景描述、缺少步骤关系的文段不标蓝。若同一句兼有两类内容，把具体数值标黄、其余流程文字标蓝；同一文字不叠加两种高亮。无法高亮的图像数据记录其图注和位置，不声称已在图像上标色。

另检查研究目标、研究内容、理论框架、研究方法、分析验证、成果和应用等段落。只有论文提供足够线索时，才综合这些段落提出技术路线图候选：梳理研究阶段、每阶段的具体任务、模块之间的顺序/并行/反馈关系，以及成果转化或应用。技术路线可跨越多个段落，属于整体研究框架，不要求与单个蓝标流程段落一一对应。区分论文明确陈述的步骤与按上下文归纳的关系；缺少支撑的阶段或应用环节不编造。

标注副本存入项目目录第一层的“输出论文”，保留原文内容、现有图片和表格。

## 2. 导出文段，交给用户选图

将论文黄标段落或表格行、蓝标段落分别保存到项目目录第一层“提取数据”中的两个 Markdown 文件；附件里的候选段落、表格行或单元格另存“附件数据摘录.md”。每条保留稳定 ID、原文、来源文件、页码或章节、表/图编号或工作表与单元格位置，以及必要上下文。将核对后的数值存入“提取数值.csv”，至少记录 data_id、source_id、变量、组别、时间点、数值、单位、误差类型与数值、来源位置、来源于附件、附件文件；缺失字段留空，不推断。

将技术路线用到、但尚未收录在黄标或蓝标文件中的论文段落摘入“技术路线图依据文段.md”，为其分配稳定 source_id，并记来源章节、页码和原文；已收录的段落沿用原 source_id。根据这些材料，在“技术路线图候选大纲.md”按 route_id 写出各候选的研究目标、阶段、每阶段 2—5 项关键任务、阶段间连线（顺序、并行或循环）、成果转化与应用，以及每一项对应的来源 ID 和明确/归纳标记。能合并的零散任务先合并；若论文仍不足以支撑这些环节，不将其列为候选，也不补造内容。

创建三份 UTF-8（带 BOM，便于 Excel 识别中文）CSV 选择清单，使用固定列名；没有技术路线候选时仍创建只有表头的技术路线图清单，并在大纲中写明原因：

| 清单 | 每行至少包含 |
| --- | --- |
| 科研图选择清单.csv | figure_id、order、data_ids、source_ids、来源于附件、附件文件、附件位置、suggested_type、是否生成、chosen_type、title、suggested_placement、notes |
| 流程图选择清单.csv | flow_id、order、source_id、topic、是否生成、direction、title、suggested_placement、notes |
| 技术路线图选择清单.csv | route_id、order、source_ids、stage_summary、relation_summary、application、是否生成、title、suggested_placement、notes |

只把证据足以成图的内容放进候选清单；每个蓝标段落都要以其 source_id 对应流程图选择清单中的一行。候选行的“是否生成”默认填“是”。清单可用电子表格或文本编辑器修改，技术路线的详细内容可在候选大纲中修改。完成提取后，**暂停生图并提醒用户**：“请打开项目目录第一层‘提取数据’中的三份选择清单和技术路线图候选大纲，检查默认‘是’的候选及附件来源；把不需要的改为‘否’，也可调整顺序、图型、方向、标题、技术路线内容和建议插入位置。保存后告诉我继续。”

一行引用多个 data_id、source_id 或附件文件时，在对应单元格中用分号分隔。只要图中任一数值来自附件，“来源于附件”就填“是”，并填写附件原文件名及页码、表格或单元格位置；论文和附件共同供数时也填“是”，在 source_ids 中保留两边证据。纯论文数据填“否”，附件字段留空。`order` 按建议插入原文的先后，在三份清单之间统一编号；用户可以修改顺序和建议插入位置。默认“是”只表示预选状态，不能跳过上述提醒和暂停。收到用户在提醒后的继续指示后，重新读取清单和候选大纲。只处理“是否生成=是”的现存行；空值、其他值及删除的行均跳过。若用户改了原文、数值或技术路线内容，先与论文或附件核对再绘图。用户可选择任意一种或多种图。

## 3. 制作已选图像

重新读取三份清单后，按 `order` 排列已选项目；相同顺序按原文位置和候选 ID 排列。依次赋予 N01、N02 等**生成顺序号**，三类图共用一个序列。候选 ID 保持不变。代码文件夹与成品图片均以“顺序号_候选ID”命名；若最终插图顺序调整，同步更新文件名、脚本输出路径、生成说明和索引。论文原有图号不占用 N 序号，新增图的正式图号按论文现有规则编排，并在索引中对应。

在项目目录第一层“过程文件/图像顺序与文件索引.csv”逐图记录生成顺序号、正式图号、图种、候选 ID、来源 ID、是否来源于附件及附件文件与位置、标题、建议及实际插入位置、代码路径、数据路径、PNG/SVG 路径、所属 PPT 与页码、生成状态。路径使用相对于项目目录的写法。每张图的“生成说明.md”写明输入、运行命令、依赖、输出及论文或附件出处，使代码与图片能一一对应。

### 科研数据图

- 为每个已选项目生成可在 VS Code 中打开的独立 `plot.py`，与其专用 `data.csv` 一起放入对应文件夹，如“过程文件/科研数据图/N01_FIG001”。脚本按自身位置解析相对路径，运行后将同编号的高分辨率 PNG（可行时另有 SVG，如 `N01_FIG001.png`）写入项目目录第一层“图片/科研数据图”。在 `data.csv` 和生成说明中保留每条数据的 source_id、附件来源及计算公式。
- 根据数据结构和研究问题，从适用的图型中选择；`suggested_type` 写清具体图型，用户可在 `chosen_type` 中修改。图型库包括但不限于：
  - **类别比较与排序：**柱形图/柱状图、横向条形图、分组条形图、堆叠条形图、分向（发散）堆叠条形图、帕累托图、棒棒糖图、点图、点状条纹图（strip/dot plot）、蜂群图、哑铃图、坡度图、子弹图。
  - **组成与层级：**饼图、环形图、矩形树图、旭日图、马赛克图、堆叠面积图、瀑布图、漏斗图、桑基图、弦图、平行集合图。饼图或环形图仅用于少量、完整且互斥的组成类别；瀑布图和漏斗图须有对应的阶段或增减数据。
  - **时间、进度与日历：**折线图、面积图、堆叠面积图、日历式热图、甘特图、时间轴图、阶梯图、事件图、控制图。甘特图需要任务及开始/结束时间或持续时间；时间趋势不能仅凭类别顺序推断。
  - **分布与统计比较：**直方图、密度图、箱线图、小提琴图、雨云图、蜂群/抖动散点图、经验累积分布图、山脊图、森林图。只有原始观测或相应统计量确实存在时才能绘制；只有均值等汇总值时，不虚构个体分布。
  - **变量关系与多维数据：**散点图、气泡图、相关矩阵/热图、日历式或矩阵式热图、等高线图、三维曲面图、雷达图/蜘蛛图、平行坐标图、分面图（small multiples）。雷达图只适用于同一尺度体系下少量可比指标，不把尺度差异误导成面积差异；相关图不暗示因果关系。
  - **流向、联系与空间：**网络图、关系弦图、桑基/流向图、地理点图、分级设色地图、气泡地图。网络边、流量或空间坐标/区域数据必须由论文或附件提供；没有地理信息时不制作地图。
  - **专题与组合图：**数据透视图（由明确的交叉分类/汇总表生成）、ROC 曲线、精确率-召回率曲线、混淆矩阵、Kaplan–Meier 生存曲线、火山图、曼哈顿图、Bland–Altman 图、双轴或多面板组合图。仅在论文数据和分析定义支持时使用，不从缺失的个体数据或模型结果反推。
- 以上是可选图型库而非必须逐一生成的清单；优先选择最容易准确解释、标注清晰的图，必要时给出一种主方案和一种可选替代方案。检查类别是否互斥、时间是否连续、数值尺度是否可比、样本量和误差定义是否明确。不要为了图型丰富而重复表达同一数据、制造没有来源的观测值，或使用与数据结构不匹配的图。只有汇总统计量时，不虚构个体分布；误差线必须注明论文报告的是 SD、SEM 还是区间。
- 使用低饱和、对比足够的灰蓝、灰绿、陶土色等配色；统一字体、标签、单位、图例和留白。检查数值与原文一致、文字可读且没有裁切。

### 流程图

- 每个已选蓝色段落对应一份 `flowchart.mmd`，放入对应文件夹，如“过程文件/流程图/N02_FLOW001”；将以顺序号和候选 ID 命名的渲染图（如 `N02_FLOW001.png`）写入项目目录第一层“图片/流程图”。所有流程图必须采用竖版、自上而下布局（Mermaid `flowchart TD` 或 `flowchart TB`），严禁使用 LR、横向主流程或宽屏横版画布。主步骤沿页面纵向排列；条件分支可在局部并排后重新汇合，整体仍保持明显的纵向长宽比。不补入论文未说明的环节。用户修改清单或原文后若不再足以支持流程，记录原因，不硬凑图。
- 使用与数据图协调的低饱和配色和清楚的节点层级，输出 SVG 和适合插入 Word 的 PNG。核对节点文字、条件标签、连线与来源段落。

### 技术路线图

- 仅为已选 route_id 制作。先按候选大纲建立“研究目标 → 阶段与任务 → 验证/反馈（如有）→ 成果转化与应用”的模块关系；阶段可依据论文内容命名为文献提炼、理论分析、实证检验等，每阶段呈现 2—5 项有出处的关键任务。明确画出论文支持的顺序、并行或循环关系；未支持的关系不画。简短标注研究方法、关键产出和应用去向。
- 采用纵向阶段布局：阶段标签、带边界的阶段分区、圆角任务模块和带箭头的连接线。主路径用较粗实线，次要或反馈路径用虚线；并行任务并列后汇合。使用统一字体、低饱和且层次分明的专业配色，以边框、线型和文字确保黑白打印仍可辨认。文字简洁，不能使用“XXX”等占位内容。
- 在“过程文件/技术路线图/N序号_ROUTE编号/route.svg”交付**完整、可直接保存和打开的 SVG 代码**，包含 `<svg>`、`viewBox`、所需的样式、圆角矩形、可编辑的 `<text>`、箭头标记及连线；不依赖外部字体文件、图片、脚本或在线资源，不能只给伪代码或片段。将同内容的 SVG 成品和供 Word 插入的高清 PNG 写入“图片/技术路线图”，按顺序号与候选 ID 命名。检查 XML 有效、节点和箭头不重叠、文字未裁切、打印对比清楚；在生成说明中写明来源段落及编辑方式。最终回复提供完整 SVG 源码文件链接；用户要求在对话中查看时，原样给出完整代码。

代码、输入数据和生成说明只放在“过程文件”；单张成品图只放在“图片”。用于组装论文或 PPT 的脚本如有生成，也存入“过程文件/组装脚本”。渲染或执行失败时保留源码，在索引中记录失败原因和缺失的图片，不把未生成文件列为成品。

## 4. 组装论文与 PPT

在最终论文副本中，将所有**已选且成功生成**的科研图、流程图和技术路线图插入首次解释它们的相关段落附近，保留原论文正文、表格及原有图片。为每张图写图号、图题和数据来源；使用附件数据的图注写明附件文件及具体表/页，论文与附件共同供数时两者都列出。核对分页、图注和嵌入图片的清晰度。标注版保存到项目目录第一层“输出论文”；最终版论文保存在项目目录根目录。

在项目目录第一层“图片”生成两份 PPTX：

- **科研数据图 PPT：**收录所有已选且成功生成的科研图。柱状图、折线图、扇形图等优先用带嵌入工作簿的 PowerPoint 原生图表，使标题、类别、系列和数值可以通过“编辑数据”修改。每张图都必须同时提供可编辑的数据表，除非已实际确认图表的嵌入工作簿可打开并修改；仅有原生图表形状或静态图片不算数据可编辑。对无法嵌入工作簿的图，在同页或紧邻的数据页放置 PowerPoint 原生表格，列出绘图所用的完整数值、类别和系列。不能用截图、SVG 或不可编辑图片代替图表与数据表。
- **流程图 PPT：**收录所有已选且成功生成的 Mermaid 流程图和技术路线图，用 PowerPoint 形状、连接线和文本框重建，使阶段、任务、节点文字与连线可单独编辑。流程图幻灯片使用竖版页面（建议宽高比 3:4 或 9:16），将主流程从上到下排布；不要制作横版流程图页。科研数据图 PPT 可按图表阅读需要使用横版页面。SVG/Mermaid 图片可作对照，不能代替可编辑主体。

某类 PPT 没有可收录的图时，仍交付该 PPTX，并用一张可编辑说明页写明本次未选择或未成功生成该类图；不把说明页算作科研图或流程图。

两份 PPT 与论文中的图保持同一编号、内容和低饱和样式。逐图提供建议插入的章节和段落线索；最终回复链接标注论文、最终论文、两份 PPT、选择清单、图像索引与过程文件中的逐图代码。

## 完成前核对

- 三份选择清单中每个“是”且成功生成的项目都有独立源码、对应数据或来源段落、图像和索引记录，并出现在相应 PPT 和最终论文中；逐一核对顺序号、文件名、正式图号及 PPT 页码。技术路线图另核对阶段、每阶段任务、连接关系、应用环节与 SVG/PPT 的一致性。未成功的项目逐项记录原因。“否”的项目不生图、不插入。
- 图中的值、单位、误差线和流程关系能追溯到论文或附件；附件来源在选择清单、过程文件、图像索引和图注中一致。计算和估读明确标记。缺失的附件、无法读取的页面或未完成的图逐项说明。
- 实际打开最终 DOCX/PDF 和 PPTX 检查显示效果与编辑性。检查科研图 PPT 中每张图的数据能否编辑：要么通过 PowerPoint“编辑数据”打开嵌入数据表，要么直接修改同页/紧邻页的原生 PowerPoint 数据表；检查流程图 PPT 的画布方向、节点和连线均为竖版、可编辑对象。若当前环境无法检查某种格式，明确写出未验证的部分。交付前检查项目目录没有本流程产生的空目录或重复的旧结构目录。
